Palsgraf / Haven · branch haven-mir-rewrite-poc

Teaching rustc to sandbox other people's code

A compiler pass that rewrites effectful calls into policy-checked shims, so MCP tool authors don't have to.

67 commits ahead of main last touched 2026-05-19 plan: haven/MIR_REWRITE_PLAN.md

The problem

Hand-wrapping every effect doesn't scale — and can't reach dependencies

To put an MCP tool inside a Haven sandbox, every effectful call in its body has to go through the runtime Transaction handle: std::fs::write(p, c) becomes txn.fs_write(p, c). Doing that by hand is tedious for one server and impossible for the crates it depends on — you can't edit reqwest's source. So we moved the rewrite into the compiler. A MIR pass clones each function body, threads a &Transaction through the clone, and swaps the effect leaves for shims. It doesn't have to be exhaustive, which is the nice part: paralegal's existing side-effect-marker analysis runs right after us and fails the build on anything we missed. Soundness turns into a build error rather than a proof obligation.

Where it hooks · before PDG construction

Paralegal grew an extension point; Haven ships its own driver

Paralegal already ran as a rustc driver, so rather than fork it we added one trait and one entry point (run_with_extension) that fires a hook after the marker context is built but before the PDG is. Haven's side is a RUSTC_WRAPPER binary, haven-driver, that depends on paralegal_flow as a library and hands it a HavenExtension. The whole extension is about forty lines — everything interesting is behind rewriter::run.

impl DriverExtension for HavenExtension {
    fn pre_pdg<'tcx>(&mut self, tcx: TyCtxt<'tcx>, markers: &MarkerCtx<'tcx>) {
        rewriter::run(tcx, markers);
    }
    // synthetic DefIds have no HIR, so we need query overrides too
    fn query_providers(&self) -> Option<fn(&Session, &mut Providers)> {
        Some(providers::install)
    }
}

Passes 1–2 · allocate, then rewrite

Every function gets a second, transaction-carrying copy

For each crate-local function we allocate a synthetic DefId with tcx.create_def whose signature is the original's plus a trailing &Transaction, mapping F → F'. Allocation happens for everything first and rewriting second, so mutual recursion just works. Functions carrying a safe marker (std:*, haven:*) and ones whose signature is contractually fixed (trait impls, extern "C") are skipped — you can't add a parameter to a trait method without breaking the trait. Closures and coroutines have the same problem, since FnMut and Future::poll fix their calling convention, so they get the transaction as an extra upvar at the tail of the captures tuple instead, and their bodies read it out of (*_1).field(N). Bodies are snapshotted lazily through a mir_promoted wrapper rather than cloned eagerly: const-eval steals MIR out from under you if you get greedy. Because synthetics have no HIR, roughly a dozen queries (fn_sig, optimized_mir, mir_borrowck, def_kind, closure_typeinfo…) get providers that answer for them and fall through to rustc for everyone else.

Traits are the gap

Closures got a workaround; trait impls didn't. They're skipped outright, so calls into them fall through to the original body and any effects inside are the analyzer's problem rather than the rewriter's. That's why the wiring protocol asks tool authors to lift each framework tool method into a plain _impl free fn or inherent method first. Redirecting <MyType as Read>::read to an inherent rewritten variant when Self is concrete is designed but unimplemented, and dyn Trait dispatch isn't addressed at all.

Pass 3 · inside the clone

Leaves become shims; the tool author writes one line

Walking a cloned body, each Call gets one of four treatments: safe-marked callees are left alone, callees we also cloned are redirected to their F' with the transaction appended, known effect leaves are swapped for the matching entry in haven_server::shim (a flat table of free fns whose signatures mirror std's plus a trailing &Transaction), and anything uncovered is left for the analyzer to reject. That leaves one question: how does the rewritten world get entered? Explicitly, at the tool's entrypoint, via a macro. haven_protected! expands to a call to a sentinel that the rewriter pattern-matches in MIR and replaces with a direct call into F'. The sentinel returns ! and is wrapped in an if false { f(args) } type anchor so .await still type-checks; if the rewriter never fires — someone built without haven-driver — it panics loudly instead of silently running unsandboxed.

// what the tool author writes
async fn protected_shell(&self, cmd: String, txn: &Transaction) -> Result<String> {
    haven_protected!(txn, Developer::shell_impl, self, cmd).await
}

// what the rewriter produces inside the clone of shell_impl
- std::fs::write(path, contents)
+ haven_server::shim::fs_write(path, contents, _txn)

Status

Working end-to-end within a crate; cross-crate is the open edge

The pipeline is real: four in-repo MCP servers are fully wrapped, with behaviour tests that compare protected output against an unprotected baseline and assert that denials actually fire, plus 22 inline rewriter tests and a clean paralegal run over the rewritten developer crate. What's not done is the motivating case — reaching into third-party bodies. transaction_referent_ty resolves per crate, so a crate that depends on haven-server threads &Transaction while one that doesn't threads &(); when the first calls into the second's clone, codegen reports NoSolution. Three fixes are written down (don't clone third-party code; clone with &() and trampoline at the boundary; inject a shared sentinel Transaction type everywhere) and the choice was deliberately deferred until a real repro forces it. It blocks the reqwest shims, which blocks financial and JotDown.

Two traps before your first build

Cargo invalidates the fixture build cache when RUSTC_WRAPPER's path changes, not its contents — after editing the rewriter, rm -rf haven/driver/test-fixtures/*/target or you'll debug cached pre-change behaviour. And reinstall cargo-paralegal-flow whenever the CLI changes: a stale binary silently falls back to the default impl and swallows the extension entirely.

Appendix

The parts that fought back

Most of the calendar time went into rustc's opinions about items that don't exist in source. Each of these was found the hard way, usually as an ICE; they're the things worth knowing before you touch the pass.

  • MIR gets stolen out from under you Cloning bodies eagerly in pre_pdg loses races: typecheck-time const-eval cascades steal mir_built and mir_promoted for anything reachable from a const expression, which in a crate like ring is a lot. The fix is to snapshot lazily from inside our own mir_promoted wrapper — when it fires for an original that's a rewrite candidate, clone the body right there, before any downstream consumer can steal it, with a fallback chain through mir_drops_elaborated_and_const_checked → optimized_mir for bodies whose earlier stages are already gone. Serving a synthetic's body also means re-anchoring body.source to the synthetic DefId, since codegen, the inliner and coverage all key off body.source.instance.
  • No HIR means a long tail of query providers A DefId from tcx.create_def has no source behind it, so every query that expects to find HIR has to be intercepted. Some can simply be fed; the HIR-derived ones (asyncness, fn_arg_idents, closure_typeinfo, whose default implementation span_bugs) need providers. check_well_formed has to skip synthetics outright or monomorphization hits unreachable!("Synthetic"), and paralegal's own reachable-marker walk drags in nested_bodies_within and opaque_types_defined_by. One genuinely obscure case: inheriting Constness::Const from a const fn original tips the synthetic into const_conditions, which bug!s on Node::Synthetic — force NotConst instead.
  • Closures take the transaction as an upvar, not an argument FnMut::call_mut and Future::poll fix the calling convention, so signature amendment is off the table for closures and coroutines; the transaction rides along as an extra capture at the tail of the upvars tuple, and redirected inner calls source it from (*_1).field(N) in a closure body or _1.field(N) in a coroutine. The consequence is at the construction site: an Rvalue::Aggregate(Closure, ..) in a cloned caller has to be substituted to build the rewritten closure, so that a generic adapter like Iterator::for_each — which we never clone, because it has no effects of its own — receives the rewritten value and dispatches into it.
  • Regions have to be wrong in exactly one place The synthetic coroutine type carries re_static on its &Transaction upvar rather than re_erased, because borrowck of any caller body that names that type walks local_decls converting regions to region vids, and '{erased} panics there. Everywhere else the region has to be erased back: the synthetic body runs through erase_regions_in_body, and the opaque-to-concrete fold that substitutes the real coroutine type into caller bodies has to erase_and_anonymize_regions first — without it, any async dispatch with non-trivial code after the .await ICEs with 'static != '{erased} in coroutine_witnesses.rs.
  • The sentinel needs a type anchor to survive inference __protected_dispatch returns ! so it coerces into any return type, but never-fallback turns that into () — and () isn't a Future, so haven_protected!(...).await wouldn't compile. Hence the if false { f(args) } else { dispatch(..) } shape: the dead branch exists purely to tell inference what the macro's type is. That shape then has to be recognised back in MIR, and the first version of the matcher was too literal — with non-Copy or method-decorated arguments, MIR construction inserts argument-evaluation calls, tuple building, Drop and Goto blocks between the SwitchInt and the dispatch, so the search has to walk through trivial terminators in both directions.
  • Async shims must be written as async fn, not with explicit lifetimes Async desugaring puts reference lifetimes into the Binder<FnSig> as anonymous late-bound regions, which is what tokio's own signatures look like. Writing a shim with named <'a, 'b> lifetimes instead changes the generics_of count and quietly breaks opaque-return matching when the rewriter tries to swap the callee. Relatedly, any opaque return type the rewriter records has to go through instantiate_bound_regions_with_erased — leaving escaping BoundVars ICEs the moment something downstream wraps the type in a dummy binder.
  • Two design calls that kept the rest simple Threading the transaction through signatures rather than a thread-local was the choice that made async work at all: std::thread_local! doesn't follow a task across .await, and tokio::task_local! would have pinned the whole design to one runtime. And bodies are cloned rather than inlined at call sites — inlining doesn't survive recursion and gets awkward around dyn dispatch — with cloning applied to everything except safe-marked items rather than pruned by reachability. That roughly doubles compile time and binary size for touched crates, which is a deliberate prototype trade with pruning left on the table.
